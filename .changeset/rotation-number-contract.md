Rotation numbers reach the contract and the tracking spec, and every inferred sport says where it came from (calchas design brief D2, 2026-10-08: a fill's `YG 913 …` rotation was parsed and then lost before it could place the bet on a doubleheader game, and calchas could not tell a stated sport from a rotation-range guess). Additive; no previously tested behavior changes except the bare-`ML` throw below.

- **`ContractLegSpec.RotationNumber` (new).** `mapParseResultToContractLegSpec` sets it from the parse for a straight, and for each parlay or round-robin leg from that leg's own number (`YGP 872 Cardinals/Cubs o8.5 @ -110 & 701 Lakers @ +120 & Yankees @ -150 = $100` maps to 872, 701 and unset). It is unset when the message has no rotation.
- **`contract.RotationNumber` is now actually set.** The stamp was guarded by `'RotationNumber' in contract`, which is always false for a freshly built contract, so the documented field was never populated; the library's own test only checked it under the same guard. Every non-writein contract parsed with a rotation now carries it, and the test asserts it unconditionally (and asserts its absence when there is no rotation).
- **`SportSource` (new) on every contract and on `ContractLegSpec`.** Set whenever `Sport` is set: `'explicit'` (sport named in the message, `IW Baseball Yankees`), `'league'` (implied by a named league, `league:NFL` / `NFL Dolphins`, and every writein sport), `'grammar'` (sport-specific grammar: an inning period or a "runs" suffix), or `'rotation'` (the existing rotation-range inference: 100-499 Football, 500-799 Basketball, 800-899 and 9900-9999 Baseball). The inference itself is unchanged, so a consumer can rank a stated sport above its own defaults and a rotation guess below them. New exported type `SportSource`; `inferSportAndLeague` additionally returns `sportSource` (same parameters).
- **A rotation with no team throws.** `YG 913 ml +100 = 1` booked a moneyline on a team named "ml". A bare `ML` marker is not a moneyline contestant (`isMoneylineContestant("ml")` is false), so this, `YG 913 F5 ml …`, `YG 913 G1 ml …` and the rotation-less `YG ml +100 = 1` throw InvalidContractTypeError. `YG 913 Rays ml +100 = 1` is unchanged.
