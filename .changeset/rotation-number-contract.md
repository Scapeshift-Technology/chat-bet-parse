Rotation numbers reach the contract and the tracking spec, and every inferred sport says where it came from (calchas design brief D2, 2026-10-08: a fill's `YG 913 …` rotation was parsed and then lost before it could place the bet on a doubleheader game, and calchas could not tell a stated sport from a rotation-range guess). Additive; no previously tested behavior changes. Five untested input shapes change: a bare `ML` now throws, a rotation guess no longer overrides a named sport or sport-specific grammar, an inning period now implies Baseball on every contract type (it did only on game totals), and a yes/no prop keeps its parsed period (`IW CIN 1st inning first team to score` was Period M/0; it is now I/1).

- **`ContractLegSpec.RotationNumber` (new).** `mapParseResultToContractLegSpec` sets it from the parse for a straight, and for each parlay or round-robin leg from that leg's own number (`YGP 872 Cardinals/Cubs o8.5 @ -110 & 701 Lakers @ +120 & Yankees @ -150 = $100` maps to 872, 701 and unset). It is unset when the message has no rotation.
- **`contract.RotationNumber` is now actually set.** The stamp was guarded by `'RotationNumber' in contract`, which is always false for a freshly built contract, so the documented field was never populated; the library's own test only checked it under the same guard. Every non-writein contract parsed with a rotation now carries it, and the test asserts it unconditionally (and asserts its absence when there is no rotation).
- **`SportSource` (new) on every contract and on `ContractLegSpec`.** Set whenever `Sport` is set, naming the strongest evidence in the message that supports that sport: `'explicit'` (sport named, `IW Baseball Yankees`), `'league'` (implied by a named league, `league:NFL` / `NFL Dolphins`, and every writein sport), `'grammar'` (sport-specific grammar: a "runs" suffix, or an inning period, which now implies Baseball on team totals, moneylines, spreads and props as it already did on game totals: `IW LAA 1st Inning TT o0.5` was sportless), or `'rotation'` (only the existing rotation-range inference supports it: 100-499 Football, 500-799 Basketball, 800-899 and 9900-9999 Baseball). So `IW 872 Athletics` is `'rotation'`, while `IW 872 Baseball Athletics` is `'explicit'` and `YG 872 Rays 1st Inning o0.5` is `'grammar'`. The inference ranges are unchanged, so a consumer can rank a stated sport above its own defaults and a rotation guess below them. New exported type `SportSource`. Internally the contract type parsers now report only grammar-implied sport, and one post-parse step applies the message-level sport and stamps `RotationNumber` and `SportSource`.
- **The rotation guess ranks last (fix).** A rotation in another sport's range used to replace a sport named without a league (`IW 872 Football Dolphins @ +145` came out Baseball; the code's own `if (!sport) sport = inferredSport` intent was defeated by a hard-coded early return) and to outrank grammar (`YG 457 Rays 1st Inning o0.5` came out Football). The guess now fills only a sport nothing else gives: those are Football `'explicit'` and Baseball `'grammar'`. Every input without such a conflict keeps its sport.
- **A rotation with no team throws.** `YG 913 ml +100 = 1` booked a moneyline on a team named "ml". A bare `ML` marker is not a moneyline contestant (`isMoneylineContestant("ml")` is false), so this, `YG 913 F5 ml …`, `YG 913 G1 ml …` and the rotation-less `YG ml +100 = 1` throw InvalidContractTypeError. `YG 913 Rays ml +100 = 1` is unchanged.
